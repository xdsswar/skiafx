# 3D Support for the Skia Pipeline

Status: **DOOR 1 IMPLEMENTED & WORKING (Windows / D3D12, bgfx)** — the
stock JavaFX 3D scene graph renders end-to-end through the bgfx pipeline.
**Door 2 has started:** glTF 2.0 model loading is implemented in the new
`javafx.scene3d` module (see §12); PBR materials and animation remain
design-only. This document is both the authoritative design and the
running status; §3 tracks Door 1, §12 tracks Door 2.
We replace Prism's 3D **entirely on the native side** with our own
renderer built on **bgfx**, **without touching the public JavaFX API**.

**Implemented (Door 1, D3D12):** `Box`/`Sphere`/`Cylinder`/`TriangleMesh`,
`PerspectiveCamera` **and** `ParallelCamera`, `SubScene` zero-copy
composite, `PhongMaterial` with all four texture maps (diffuse/specular/
bump/self-illum, mipmapped, UV+TBN), the unified light model (ambient +
point/spot/directional with attenuation, spot cone + falloff and range;
up to **8** lights vs stock's 3), back-face culling (`CullFace`),
wireframe (`DrawMode.LINE`), true **MSAA 4×** + per-`SubScene` runtime AA
toggle, 3D picking and `SubScene.snapshot()`. Texture uploads are deduped
by source image (one refcounted GPU texture shared across materials) and
throttled across frames to keep the cold start smooth.

**Beyond stock (opt-in increments, D3D12):** tangent-space **normal/bump
mapping** (full TBN path, verified end-to-end — any PNG/JPG normal map
works, e.g. the code-generated one in Demo3D; the bundled sets ship EXR
normals which the JavaFX image loader can't decode) and a first
**shadow-mapping** pass (single fixed directional sun, whole-scene ortho
frustum, 4-tap PCF; enable with `OPENJFX_SKIA_3D_SHADOWS=1` — off by
default). See §10.3.

**Not yet:** OpenGL/Vulkan/Metal backends (D3D12-only today; see §11
Phase 3D-E), Door 2 model loading / PBR / animation, the macOS Metal
device-injection spike, and a per-light / per-`SubScene` shadow API
(today's shadow is a single hard-wired sun). Full metallic-roughness
**PBR** is Door 2.

Audience: contributors implementing the 3D path. The project-wide constraints
bind this work: public API frozen, native-first, zero-copy, bounded GPU memory,
cross-platform, open and free (no Skija — the bridge is our own native Skia layer).

## 0. TL;DR — the decisions

- **Engine: bgfx** (BSD-2-Clause, 100% open, no commercial components).
  Chosen over Diligent (commercial Metal backend), Filament (cannot share
  a device → no zero-copy), and a hand-written renderer (too much work to
  reach real capability).
- **Public JavaFX API: unchanged.** Not one line of `javafx.scene.*`
  changes. We swap Prism's 3D implementation for a bgfx-backed one on the
  **native side**, behind the existing internal hooks.
- **Two doors, one engine:**
  - **Door 1 — parity.** The existing JavaFX 3D scene graph
    (`Box`/`Sphere`/`Cylinder`/`MeshView`/`PhongMaterial`/cameras/lights/
    `SubScene`) renders through bgfx instead of Prism. Phong shading,
    pixel-near to stock. Zero public-API change, minimal internal change.
  - **Door 2 — capability.** New *additive* API (new package) for things
    stock JavaFX 3D never had: glTF model loading, skeletal + morph
    animation, PBR materials, the building blocks for 3D games / 3D maps.
    Opt-in; runs on skia-fx, not on stock OpenJFX. Never modifies the
    frozen public API.
- **Zero-copy is the keystone.** bgfx renders into a GPU texture **we
  create on Skia's own device**; that same native texture is wrapped by
  Skia via `SkImages::BorrowTextureFrom` and composited — no copy.
- **Backends:** D3D12 + OpenGL on Windows, Vulkan + OpenGL on Linux,
  **native Metal** on macOS — all open. (No reliance on Apple-deprecated
  GL for the Mac shipping path.)

## 1. The core problem: Skia is a 2D rasterizer

This is the single fact that dictates the whole design. Verified against
current Skia:

- **Ganesh (our GPU backend) has no application depth buffer and no
  z-test.** 2D content is composited by the painter's algorithm (draw
  order), never by per-pixel depth.
- **`SkCanvas::drawVertices` / `SkVertices` is 2D only** — positions are
  `SkPoint` (x, y); no z, no perspective-correct depth, no hidden-surface
  removal.
- **`SkM44` + `SkCanvas::concat(SkM44)` and the deprecated
  `Sk3DView`/`SkCamera` are projective 2D transforms** — good for a
  card-flip, useless for intersecting solid geometry.
- **`SkRuntimeEffect` (SkSL)** is per-pixel fragment math inside one 2D
  draw — no vertex stage you control, no depth buffer.
- **Graphite** uses a depth buffer internally only as a 2D
  overdraw/clip optimization; it exposes no 3D scene API. Moving to
  Graphite later does **not** change this design.

**Conclusion: real 3D must be rendered by a real 3D pipeline that shares
Skia's GPU device, renders into an offscreen color + depth target, and
hands the color texture to Skia as an `SkImage` to composite into the 2D
scene.** This is exactly how Chromium composites WebGL/WebGPU into a
Skia-drawn page, and how Flutter does 3D (Impeller renders 3D, Skia only
2D). It is the industry pattern, not a workaround.

## 2. Why bgfx (engine evaluation)

We need an engine that is, in priority order: (1) **zero-copy** — can
render on a device Skia already created; (2) **fully open & free**; (3)
**native, future-proof Metal** on macOS (GL is deprecated by Apple); (4)
**capable** — a path to glTF/animation/PBR; plus cross-platform, fast,
memory-bounded.

| Engine | Open & free | Shares Skia's device (zero-copy) | Native open Metal | glTF/anim/PBR built-in | Verdict |
|---|---|---|---|---|---|
| **bgfx** | ✅ BSD-2 | ✅ `PlatformData` (GL/D3D/Vulkan verbatim; Metal to confirm) | ✅ in-tree | ❌ build on top | **Chosen** |
| Diligent | ⚠️ Metal backend **commercial** | ✅ D3D12/GL/Metal attach | ❌ (Metal commercial) | ✅ | Rejected — Mac path not open |
| Filament | ✅ Apache-2.0 | ❌ owns its device → 1 copy | ✅ | ✅✅ | Rejected — breaks zero-copy |
| Hand-written | ✅ ours | ✅ perfect | ✅ (we write it) | ❌ multi-year | Rejected — capability cost |

bgfx is the only option that satisfies **all four** hard constraints. The
price is that bgfx is a rendering *abstraction*, not a turnkey engine: it
has **no glTF loader, no animation system, no PBR renderer**. We build
those (Door 2) — but they are **net-new capability beyond any JavaFX**,
built **once** on bgfx and running identically on D3D12, Vulkan, and
native Metal.

### Verified bgfx facts (from bgfx headers/docs, master)

- **License:** BSD-2-Clause. Metal (`src/renderer_mtl.mm`), D3D12
  (`renderer_d3d12.cpp`), Vulkan (`renderer_vk.cpp`) all open, in-tree.
  Only console backends (GNM/NVN/AGC) need vendor NDA SDKs — irrelevant
  to desktop.
- **Backends (`RendererType::Enum`):** Noop, Direct3D11, Direct3D12,
  Metal, OpenGL, OpenGLES, Vulkan, WebGPU (+ console). Per-platform
  mapping is *inferred* (bgfx publishes no authoritative table — confirm
  empirically): Win = D3D11/D3D12/Vulkan/GL; Linux = Vulkan/GL; macOS =
  Metal.
- **Device sharing — `bgfx::PlatformData`:**
  ```cpp
  struct PlatformData {
      void* ndt;          // native display (X11/Wayland)
      void* nwh;          // native window handle; NULL => headless device
                          //   "provided the rendering API supports it"
      void* context;      // "GL context, D3D device, or Vulkan device.
                          //   If NULL, bgfx will create context/device."
      void* queue;        // "D3D12 Queue. If NULL bgfx will create queue."
      void* backBuffer;   // GL back-buffer / D3D RTV; NULL => bgfx creates
      void* backBufferDS; // backbuffer depth/stencil; NULL => bgfx creates
      NativeWindowHandleType::Enum type; // Default(X11)/Wayland
  };
  void bgfx::setPlatformData(const PlatformData&); // before bgfx::init
  ```
  `context` is documented for **GL / D3D / Vulkan**; `queue` for D3D12.
  **Metal is NOT named in the `context` doc → the single load-bearing
  unknown.** Validate via spike + reading `renderer_mtl.mm` (it is open).
- **Bind a native texture into bgfx — `overrideInternal`:**
  ```cpp
  // wrap an EXISTING native texture into a bgfx TextureHandle:
  uintptr_t overrideInternal(TextureHandle h, uintptr_t nativeTexPtr,
                             uint16_t layerIndex = 0);
  // or have bgfx (re)create + return the native pointer:
  uintptr_t overrideInternal(TextureHandle h, uint16_t w, uint16_t hgt,
                             uint8_t numMips, TextureFormat::Enum fmt,
                             uint64_t flags = BGFX_TEXTURE_NONE|BGFX_SAMPLER_NONE);
  ```
- **Offscreen RT:** `createTexture2D(w,h,hasMips,numLayers,format,
  flags=BGFX_TEXTURE_RT,...)` for color + depth, then
  `createFrameBuffer(num, TextureHandle*, destroyTexture=false)` to
  attach them.
- **Native handle discovery:** `getInternalData()` returns
  `{ const Caps* caps; void* context; }` — the **device**, not a texture.
  `getDirectAccessPtr()` is **CPU/UMA** access (gated by
  `BGFX_CAPS_TEXTURE_DIRECT_ACCESS`) — **wrong tool**, do not use it for
  GPU sharing.
- **Shaders:** author `.sc` (GLSL-like) + `varying.def.sc`, compile with
  `shaderc` to DXBC/DXIL, **SPIR-V**, **Metal (`-p metal`)**, GLSL/ESSL.
  One source → all backends.
- **Threading:** API thread + render thread. Call `bgfx::renderFrame`
  **before** `bgfx::init` on the intended render thread to stop bgfx
  spawning its own thread; if `init` and `frame`/`renderFrame` run on the
  **same** thread, bgfx switches to single-threaded mode (`bgfx::frame`
  calls `renderFrame` inline). `bgfx::Encoder` for multi-threaded submit.
- **No public cross-renderer barrier/fence API.** When Skia reads a
  bgfx-written texture, **we** own ordering and (D3D12/Vulkan) resource
  state transitions on the native side. The safe envelope: bgfx
  single-threaded on Skia's render thread, bracket bgfx work with
  `bgfx::frame()`.
- **Build:** GENie natively; **`widberg/bgfx.cmake`** (public domain) for
  CMake consumption — fits our Gradle→CMake pipeline. C++ standard not
  officially pinned (~C++14-era) — confirm for our toolchain.
- **Maturity:** mature, widely used — Minecraft (Bedrock), Guild Wars 2,
  Football Manager 2024, Crypt of the NecroDancer, HARFANG 3D, etc.

Vertex/material formats we must consume (from upstream
`com.sun.prism.impl.BaseMesh`):

- **Interleaved vertex** = 9 floats: `pos.xyz (3)`, `texCoord.uv (2)`,
  `normal as quaternion xyzw (4)`. `BaseMesh` already builds this,
  generates normals from smoothing groups, computes tangents, and dedups.
  **Reuse `BaseMesh`'s geometry compilation; implement only the bgfx
  vertex/index upload + draw**, like `ES2Mesh`/`D3DMesh` do.
- **PhongMaterial:** `diffuseColor (rgba)`, `specularColor + power`,
  maps `diffuse/specular/bump(normal)/selfIllum`, 1×1 white placeholder
  for absent maps.
- **Lights:** position (xyz), color (rgb), `w` (1=point/spot,
  0=directional), attenuation (const/linear/quadratic), direction (xyz),
  spot inner/outer angle + falloff, plus one ambient term. **Pin the
  exact light-count cap from the upstream backend shader / `NGShape3D` —
  verify against `/jfx-master`, do not guess.**
- **Camera:** `NGCamera` gives a `GeneralTransform3D projViewTx` + near/
  far → MVP for the vertex stage.

## 5. Architecture — bgfx renderer sharing Skia's device

```
                 skia-fx render thread (ONE OS thread)
   ┌────────────────────────────────────────────────────────────┐
   │ GrDirectContext  (built from a backend context WE own)      │
   │   device/queue:  D3D12: ID3D12Device + ID3D12CommandQueue   │
   │                  GL:    GL context / GrGLInterface          │
   │                  Vulkan:VkDevice + VkQueue                  │
   │                  Metal: id<MTLDevice> + MTLCommandQueue     │
   └───────────────┬────────────────────────────┬───────────────┘
                   │ SAME device                 │ SAME device
                   ▼                             ▼
        Skia 2D (SkSurface/SkCanvas)   bgfx (PlatformData.context = device,
                   ▲                            .queue = D3D12 queue,
                   │ drawImage(SkImage)         .nwh = NULL  → headless)
                   │                            │ renders SubScene
                   │                            ▼ into a texture WE created
                   │  zero-copy wrap     ┌──────────────────────────┐
                   └─────────────────────┤  color tex (ours) + DEPTH │
        SkImages::BorrowTextureFrom      │  overrideInternal(h, tex) │
        (GrBackendTexture from the       │  → bgfx draws into it     │
         SAME native texture)            └──────────────────────────┘
```

### The zero-copy mechanism (recommended, from verification)

**Create the color render-target texture yourself, on Skia's device, and
hand the *same* native texture to both Skia and bgfx.** This is cleaner
than letting bgfx allocate and reading its handle back (whose return is 0
until lazy creation — timing-fragile).

Per SubScene render target, on the render thread:

1. **Create the native color texture** (`ID3D12Resource*` /
   `id<MTLTexture>` / `VkImage` / GL id) and a depth texture on Skia's
   device, sized to the subscene.
2. **Give the color texture to bgfx:** make a bgfx `TextureHandle`
   (`createTexture2D(..., BGFX_TEXTURE_RT)`), then
   `overrideInternal(handle, (uintptr_t)nativeColorTex)`; build a depth
   RT the same way; `createFrameBuffer(2, {color, depth})`.
3. **Render the subscene** with bgfx into that framebuffer (depth test
   on, cull per node, Phong shader, MVP from the camera). `bgfx::frame()`
   to flush bgfx's command stream on this thread.
4. **Transition + sync (native side, our responsibility):** D3D12 →
   transition the color resource to the read state Skia expects and call
   `GrDirectContext::setBackendTextureState()`; GL → `resetContext()` (+
   `resetGLTextureBindings()` if textures were rebound); Vulkan/Metal →
   image layout / ordering. bgfx exposes no barrier API — we own this.
5. **Wrap the *same* native texture for Skia:** build a
   `GrBackendTexture` (`GrD3DTextureResourceInfo` / `GrGLTextureInfo` /
   `GrVkImageInfo` / Metal) and `SkImages::BorrowTextureFrom(...)`.
6. **Composite:** `canvas->drawImage(...)` at the subscene's node bounds
   — zero copy. Counted by `gpu_copy_counter` as a *wrap*, not a copy.

### Threading

bgfx runs **single-threaded on Skia's render thread**: call
`bgfx::renderFrame()` once from that thread *before* `bgfx::init`, or run
`init` + `frame` on it so bgfx auto-selects single-threaded mode. This is
mandatory on Metal/GL where the device/context is thread-affine, and it
gives natural submission ordering on the shared queue. Do not let bgfx
spawn its own render thread.

### Per-OS backend matrix

| OS | bgfx 3D backend (native, open) | Skia 2D backend it shares | Device handed to bgfx | Zero-copy | Open |
|---|---|---|---|---|---|
| **Windows** | Direct3D12 | D3D12 (`OPENJFX_SKIA_D3D=1`) | `context`=`ID3D12Device`, `queue`=`ID3D12CommandQueue` | ✅ | ✅ |
| **Windows (alt)** | OpenGL | GL (default) | `context`=GL context | ✅ | ✅ |
| **Linux** | Vulkan | Vulkan | `context`=`VkDevice` | ✅ | ✅ |
| **Linux (alt)** | OpenGL | GL | `context`=GL context | ✅ | ✅ |
| **macOS** | **Metal** | Metal | `context`=`id<MTLDevice>` ⚠️ **(spike-confirm)** | ✅* | ✅ |

\* macOS zero-copy depends on the Metal device-injection spike (§11).
Fallback if it fails: bgfx-Metal on its **own** device + one composite
copy (still open, still native Metal — just not zero-copy on Mac).

**Coupling to know:** keeping zero-copy 3D means Skia's 2D backend and
bgfx's 3D backend must run on the **same** device per platform (both
D3D12, or both GL, or both Vulkan, or both Metal). Mixed backends → fall
back to a separate bgfx device + one copy.

### 6.3 `SkiaRTTexture` depth attachment

Add a depth-bearing `createRTTexture` overload. When 3D is in play the RT
must allocate a native offscreen target **with a depth buffer** (and
optional MSAA color) on the shared device — not the raster SkSurface it
makes today. `NGSubScene` is the caller. The color attachment must be
wrappable both as a Skia render target (for any 2D children drawn into
the subscene) and as a `GrBackendTexture` (for the final composite).

```
openjfx_skia3d_meshview_destroy(mv)                          -> void
openjfx_skia3d_draw(target, meshview, mat,
                    mvp[16], normalMat[9], camPos[3],
                    cull, wireframe,
                    ambient[3], lights*, lightCount)         -> int32_t
```

Every handle gets a `Cleaner`-registered destroy (the project's native-handle
lifecycle rule); no `finalize`. Per-frame uniform/light arrays go through
`FrameArena`, not fresh allocations.

## 8. Door 2 — capability API (additive; glTF, animation, PBR, maps)

JavaFX's frozen 3D API **cannot express** glTF/skeletal animation/maps,
so Door 2 is **new additive API in a new package** (the same additive, opt-in
pattern the project allows for new capabilities). Rules:

- **No public-API modification.** New types in a new package; never touch
  `javafx.scene.*`.
- **No native/engine leakage in signatures** — no bgfx types, no
  handles/ids, ever (project rule). FX-thread `Consumer<T>` callbacks,
  **not** `CompletableFuture` (project rule). A new node type hosts the
  3D scene and composites via the **same** zero-copy handback as Door 1.
- **Compat caveat:** apps using Door 2 run on skia-fx, not on stock
  OpenJFX 25 — acceptable for new, clearly-namespaced API.

Built on bgfx + open libraries:

| Capability | How | Open dep |
|---|---|---|
| glTF 2.0 loading | parse → bgfx VB/IB + textures | cgltf or tinygltf (MIT) |
| PBR materials | metallic-roughness + IBL shaders in `.sc` → all backends | ours |
| Skeletal (skinning) | joint-matrix palette, skin in vertex shader | ours (glTF supplies skins/joints) |
| Morph targets | blend targets by weight in vertex shader | ours |
| Advanced (shadows, instancing, LOD, 3D maps/games) | built on the above | ours; maps are app-level |

Honest scope: Door 2 ships the **building blocks** for "3D games / a 3D
Google Maps." A full maps app (tiled terrain streaming, geospatial
projection, LOD) is an **application** built on those blocks, not SDK
scope.

## 9. SubScene compositing & depth

`NGSubScene.renderContent(g)` already orchestrates correctly; we fill the
contents:

1. `rf.createRTTexture(w, h, depthBuffer=true)` → a `SkiaRTTexture`
   backed by a native bgfx target **with depth** (not raster).
2. `g2 = rtt.createGraphics()`; `g2.setCamera`, `g2.setLights`,
   `g2.setDepthBuffer(true)`.
3. Clear to the subscene `fill`. Render 3D children → native
   `openjfx_skia3d_draw` per mesh with depth test on. 2D children inside
   a 3D subscene draw via the normal Skia path into the same target's
   color (depth test off for 2D, matching `Node.depthTest`).
4. Composite: wrap the target color as `SkImage`
   (`BorrowTextureFrom`) and `g.drawTexture(rtt, …)` — zero copy.

**MSAA / `SceneAntialiasing`:** MSAA color attachment; resolve to a
single-sample texture before wrapping for composite (mirror upstream's
RTT + resolveRTT). Honor `DISABLED/BALANCED/QUALITY` by sample count.

**Depth semantics:** 3D nodes default `depthTest=true`; 2D nodes
`depthTest=false`. One depth buffer per subscene render; budget and reuse
across frames (don't reallocate per pulse).

**Transforms/clips/opacity on the SubScene node** apply for free because
the composite is a normal `drawImage` — confirm with a `SubScene` under
opacity + rotation.

## 10. Memory, copies, instrumentation (non-negotiable)

- **Zero-copy composite.** The 3D→Skia handback uses `BorrowTextureFrom`;
  never reads back to CPU. Counted in `gpu_copy_counter` as a *wrap*.
- **GPU budgets.** New categories: "3D render targets (color+depth)",
  "3D mesh VB/IB", "3D textures (Phong/PBR maps)". Soft/hard caps + LRU
  eviction. No unbounded growth.
- **Native lifecycles.** Every mesh/meshview/material/target handle is
  `Cleaner`-registered and `AutoCloseable`; no `finalize`. Verify no leak
  across a soak run.
- **No per-frame heap on the render thread.** MVP/normal-matrix/light
  arrays via `FrameArena`; reused handles; index-based loops.
- **One device, shared.** bgfx never creates a second device/context.
  Survives resize/focus-loss like the 2D context.

### 10.1 Errors must never kill the JVM (hard rule)

No 3D/shader failure may crash the process (the project's errors-never-kill-the-JVM
rule; doubly important here — much of this surface is driven by *app-supplied*
meshes/materials/shaders and by fallible GPU state).

- **No `abort()`/`assert`/unchecked crash** in native 3D or shader code.
  Validate inputs; return failure codes (null handle / negative status)
  for bad indices, null handles, degenerate geometry, OOM, shader-compile
  failures.
- **Native failure → Java exception or graceful no-op, never SIGSEGV.**
  Catch C++ exceptions at the FFM boundary; guard every foreign-pointer
  deref.
- **Bad app shader source must not crash** — compile errors return
  diagnostics + a catchable Java exception; a draw-time shader failure
  falls back to a safe default (flat/passthrough), never aborts the frame.
- **Render-time failures degrade** — skip the failing node/subscene, keep
  rendering the rest (mirror `SkiaPassthroughPeer`).
- **GPU device loss never crashes** — every native 3D entry point guards
  `d3d12_device_lost()` and degrades to a no-op (see §10.2 for the
  handle-validity guards and the recovery status).
- **Diagnostics via the project logger** behind a verbose flag — never
  per-frame `System.err` or native `printf` on the render thread.

### 10.2 Handle-validity guards + device-loss recovery (status)

**Foundation — DONE (Phase 1a).** Every native 3D resource struct
(`Mesh3D`/`Material3D`/`MeshView3D`/`Target3D`) carries a per-type `magic`
tag (poisoned to 0 on destroy) and a `deviceGen` stamp. The `as*()` guard
helpers reject a null / wild / already-destroyed / wrong-type / stale-
generation handle before any dereference or GPU call, every entry point
goes through them, destroys poison-first (double-destroy is a no-op) and
only `bgfx::destroy` on the live generation, and a central registry
(`gMeshes`/`gMaterials`/`gMeshViews`/`gTargets`) tracks all live resources.
Net: a bad handle from Java is never dereferenced — "never use destroyed
or unreferenced GPU resources" holds for the whole bridge.

**Full device-loss RECOVERY — DEFERRED (was Phase 1b).** Recreating the
device + bgfx + resources to *resume* rendering after a real GPU reset is
deferred. A spike established the blocker: bgfx and Skia **share one
D3D12 device/queue**, and while `bgfx::shutdown()` is safe (with a
pre-shutdown GPU-queue drain — verified: 2D keeps running, no crash),
calling `bgfx::init()` a **second time** on that shared device corrupts
the shared D3D12 state (`STATUS_STACK_BUFFER_OVERRUN`). So in-process bgfx
re-init is unsafe with the shared-device architecture. The `deviceGen`
field is the inert hook the recovery will bump.

Why deferring is acceptable today: the main historical device-loss
trigger (the cross-DPI monitor-move TDR) is **already fixed** (swapchain
`E_ACCESSDENIED` + device-lost guards), so real device loss is rare, and
the no-crash rule is **already met** by the guards above. When recovery is
revisited, the viable paths are: (a) recreate the **2D** device/Skia-
context/swapchains and leave **3D** down until app restart (brings the
window back after a GPU reset; verified-safe teardown exists), or (b) give
bgfx its **own** device + a cross-device composite copy (loses zero-copy),
or (c) fix bgfx's in-process re-init. This pairs naturally with the
cross-platform backend work (§11 Phase 3D-E) — each backend (GL/Vulkan/
Metal) needs its own device-recreate, behind the same generation/registry
architecture.

### 10.3 Shadow mapping (first increment — opt-in)

A first shadow-map pass is wired into the Door-1 renderer and **off by
default** (enable with the `OPENJFX_SKIA_3D_SHADOWS=1` environment
variable; `runDemo3D` sets it). It is intentionally a minimal, correct
foundation rather than the final API:

- **One fixed directional sun.** `ensureShadowResources()` builds a fixed
  light view-projection (`bx::mtxLookAt`/`mtxOrtho`, dir ≈
  `normalize({0.35, 1.0, 0.25})`, whole-scene ortho frustum) — it is **not
  yet** derived from the scene's actual `LightBase` nodes. A per-light /
  per-`SubScene` shadow API is the next refinement.
- **Depth-from-light pass.** bgfx view `kViewShadow` (0) renders scene
  depth into a `2048²` **R32F** shadow map (+ D32F depth) via
  `vs_shadow`/`fs_shadow`. The main Phong pass then samples it.
- **PCF comparison in `fs_phong`.** `shadowFactor()` does the NDC divide,
  HLSL/Metal/SPIRV Y-flip, an out-of-frustum early-out (= lit), and a
  4-tap `texture2DLod` PCF (explicit LOD 0 — a gradient-taking sample in
  that path is illegal in HLSL). Shadowing dims only the direct
  (diffuse + specular) terms; **ambient is unshadowed** so occluded
  surfaces never go fully black. Params (`u_shadowParams`): enable, depth
  bias (`0.0025`, against acne), strength (`0.6`).
- **Render-thread + guard-clean.** The shadow resources live in a
  file-scope `ShadowState gShadow`, are created lazily under the device-
  loss / handle-validity guards (§10.2), and add **no per-frame heap
  allocation**. Wireframe draws skip the depth pass.

Verified by `runDemo3D -Pskia.3d.selftest=true` (soft shadow blobs cast on
the floor under the sphere/cylinder/cube, with the shapes retaining their
normal-mapped surface detail). Open follow-ups: drive the light from the
scene's real lights, cascaded/​tunable maps, and a public (handle-free)
toggle/quality API — these land with the broader material-quality phase.

## 12. Door 2 — `javafx.scene3d` & glTF 2.0 loading (IMPLEMENTED, increment 1)

Door 2 is the *additive* capability layer that stock JavaFX 3D never had. It
lives in a **separate JPMS module, `javafx.scene3d`** (public package
`javafx.scene.model3d`), so the base 3D in `javafx.graphics` stays lean. The
module name avoids `javafx.3d` because a JPMS/package name segment can't start
with a digit.

**Architecture — handle-free, zero new rendering.** A glTF model maps onto the
*existing public* JavaFX 3D scene graph: `Group` → `MeshView` → `TriangleMesh`
(`POINT_NORMAL_TEXCOORD`) + `PhongMaterial`. The loader produces a standard
`javafx.scene.Node` subtree that renders through the already-working Door-1
bgfx pipeline — so there is **no new rendering code** and the public API
**never exposes a native handle** (memory `no-ids-handles-in-public-api`). The
native lib's only job is parsing.

**Public API (sugar).** Static one-liners on
`javafx.scene.model3d.ModelLoader`:
```java
Node model = ModelLoader.load("assets/robot.glb");   // also load(Path), load(InputStream)
```
Returns a `Group`. Throws `IOException` on an unreadable/invalid asset.

**Native lib `openjfx_model3d`** (`javafx.scene3d/src/main/native/`,
cgltf-based, **no Skia/bgfx/D3D dependency**). It does the heavy work in C++
and hands back JavaFX-ready arrays:
- parses `.glb`/`.gltf` (cgltf v1.14, vendored single header);
- decodes accessors (sparse / normalized / strided / u16+u32 indices);
- builds **the interleaved faces array directly** (`[p,n,t]` per vertex) plus
  points / normals / texcoords, so Java only stuffs them into a `TriangleMesh`.
- **Owns a copy of the input buffer** for the session lifetime — cgltf keeps
  pointers into the GLB bin/JSON, so the session must not alias the caller's
  (transient FFM) buffer. *This was the one real bug found in bring-up: a
  use-after-free that produced garbage indices nondeterministically.*
- Handle-guarded ABI (magic tag, poisoned on close; double-close is a safe
  no-op; every entry validates before dereference; errors return codes, never
  crash — memory `errors-never-kill-jvm`).

**Java glue** (`com.sun.javafx.model3d`, module-internal): `NativeModelBridge`
(FFM; the native `long` handle never leaves the package) + `GltfSceneBuilder`
(assembles the scene graph). Key correctness choices, all verified against the
JavaFX `TriangleMesh`/`PhongMaterial` source:
- **Handedness:** glTF is right-handed +Y-up; JavaFX is Y-down. A single
  determinant-negative root `Scale(1,-1,1)` reconciles them — `NGShape3D`
  auto-swaps the cull face on a negative determinant, so glTF CCW front faces
  stay correct under the default `CullFace.BACK`. Winding is **not** reversed
  (that would double-correct). No texcoord-V flip (both use top-left UV origin).
- **Normals** passed through verbatim when present (`POINT_NORMAL_TEXCOORD`);
  when absent, `POINT_TEXCOORD` lets the renderer generate them.
- **Self-validation** of index ranges before handoff — `TriangleMesh` drops a
  mesh *silently* (empty bounds + a log line) on a bad index, so the builder
  checks first.
- **Materials:** baseColorFactor→diffuseColor (alpha clamped ≥1/255),
  baseColorTexture→diffuseMap, **normalTexture→bumpMap** (already a tangent-
  space normal map — works today), emissive→selfIlluminationMap (1×1 image for
  factor-only), metallic/roughness→an approximate specular term (real PBR is a
  later increment). Textures are PNG/JPEG via `javafx.scene.image.Image`;
  KTX2/EXR are skipped (kept solid-color).

**Build/packaging.** Standard conventions: the native lib ships at the jar root
with a SHA-256 `checksums.properties`, `NativeLibLoader` extracts it on first
use, `collectIntoSdk` populates `sdk/lib`, and `buildAll` includes the module
automatically. `javafx.graphics` exports `com.sun.glass.utils` to
`javafx.scene3d` so the loader reuses `NativeLibLoader`.

**Verified.** `:samples:ensemble:runModelDemo` shows a loaded model (drag-orbit,
scroll-zoom); `-Pmodel.selftest=true` runs headless asserts — Box (12 tris),
BoxTextured (12 tris, diffuse map), Duck (4212 tris, textured) all load;
garbage bytes are rejected as `IOException`; a 50× load/close loop shows no
crash or leak (open/close parity, session-owned buffer freed each time).

**Scope (this increment) / next.** In: `.glb`/`.gltf`, TRIANGLES,
POSITION/NORMAL/TEXCOORD_0, node hierarchy + transforms, PhongMaterial mapping,
PNG/JPEG textures. Next increments (additive, mostly in `javafx.scene3d`):
true metallic-roughness **PBR** material (`fs_pbr` + new public material type),
**skeletal/morph animation**, **GPU instancing**, and Draco/KTX2/multi-UV.

## 14. Custom shaders (passing shaders from JavaFX)

Status: **DESIGN / placeholder.** Separate from the 3D scene graph but
related. Stock OpenJFX has **no** public shader API, so anything here is
**new, additive, opt-in** surface (won't run on stock OpenJFX).

### 13.1 Case 1 — 2D custom shaders via `SkRuntimeEffect` (clean path)

Skia's `SkRuntimeEffect` compiles **SkSL** from a runtime string into an
`SkShader`/`SkColorFilter`/`SkBlender`. **One SkSL source cross-compiles
to whichever Ganesh backend is live** — write once, Skia emits the
per-platform variant. Rides existing bridge plumbing
(`shader_create_*`/`filter_create_shader`); the resulting `SkShader`
flows into existing `fill_*_shader` draw paths or wraps as a node effect.
**Independent of the 3D work; can land first.**

### 13.2 Case 2 — custom 3D materials (harder)

The §7 3D renderer is bgfx-native, so custom 3D *materials* compile
through **bgfx `shaderc`**, not Skia's SkSL. Realistic target: a
**fragment-only** custom material (app supplies shading math; we own the
vertex stage, MVP, normals, lighting uniforms) authored in bgfx's `.sc`
dialect, compiled to all backends. Treat as a Phase 3D follow-on.
